How to Use the User Data Directory

Use this directory for resources you want to share between different installs or versions of MegaMek, MegaMekLab and MekHQ. Because it lives outside the installation, its contents survive upgrades. The directory should be an absolute path such as D:/MyBTStuff (in other words, not relative to your MegaMek directory).

The same setting is shared by all three programs. It can be set in MekHQ under File > MekHQ Client Options > Advanced > User Files Directory, in MegaMek's client settings, or in MegaMekLab's settings. The MegaMek Launcher can also supply a directory for a single run (the megamek.userDir system property), which takes precedence over the saved setting.

Generally, content in the user directory is added to the content that ships with the programs. In some cases it replaces shipped content with the same name, code or file path; those cases are noted below. Most content is read at startup, so restart after adding files unless the relevant screen has a refresh button.

Do not confuse this with the userdata folder inside each installation. That folder is part of the install and is not shared between installs or carried across upgrades.

Shared by MegaMek, MegaMekLab and MekHQ

  • Fonts (.ttf files) can be placed anywhere in the user data directory (i.e., in the directory itself or in any subfolder).
  • Units (.mtf, .blk, .mep, .hmv, .tdb, .hmp and .bfs files, or .zip files containing them) can be placed anywhere in the user data directory. Folders named unsupported or .mml_tmp are skipped.
  • Camo images must be placed in <user data directory>/data/images/camo/. In this subfolder, further subfolders can be used (optional).
  • Portrait images must be placed in <user data directory>/data/images/portraits/. In this subfolder, further subfolders can be used (optional). For MekHQ's random portraits, see Portrait Generation.md in this folder for the folder names that are used.
  • Unit fluff images (.png, .jpg, .jpeg or .gif) must be placed in <user data directory>/data/images/fluff/<unit type>/. The unit type folders are Mek, ProtoMek, BattleArmor, Infantry, Vehicle, Fighter, ConvFighter, Small Craft, DropShip, JumpShip, WarShip, Space Station and Asset. An image is used for a unit when its file name matches the unit's model or chassis (anything after an underscore is ignored, so Atlas_alt.png matches every Atlas). Images can also be sorted into <unit type>/<chassis>/ or <unit type>/<chassis>/<model>/ folders, where every image in the folder matches. Images in the user directory are preferred over the shipped ones.
  • Record sheet images, used in preference to fluff images when printing record sheets, can be placed in <user data directory>/data/images/rs/<unit type>/, using the same unit type folders and naming as unit fluff.
  • Factions and commands: YAML files (.yml, or .zip files containing them) can be placed in <user data directory>/data/universe/factions/ and <user data directory>/data/universe/commands/. A file with the same faction key as a shipped faction replaces it. See Faction Logos below.
  • Faction icons (.png) can be placed in <user data directory>/data/images/universe/factions/. An icon there replaces a shipped icon with the same file name.
  • Bloodnames: YAML files (.yml) can be placed in <user data directory>/data/universe/bloodnames/.

MegaMek

  • Skin definition files (.xml) can be placed anywhere in the user data directory.
  • Scenarios (.mms files) can be placed in <user data directory>/data/scenarios/. Subfolders can be used, and the first subfolder level is shown as a group in the scenario chooser.

MegaMekLab

The user directory is used to restore your most recent session. If you set the startup mode of MegaMekLab to "Restore Tabs", a hidden folder called .mml_tmp is created in your user directory. You should not touch this folder; changing its contents may cause MegaMekLab to fail to start. If "Restore Tabs" is set and MegaMekLab is failing to start, try deleting the .mml_tmp folder, in case it was corrupted.

MekHQ

  • Formation icons (formerly force icons) must be placed in <user data directory>/data/images/force/. The directory structure of this folder should mirror that in your MekHQ folder at /data/images/force/: layered icon pieces go in the matching folders under Pieces/, and unit icons in Units/. See Force_Icons.md in this folder.
  • Rank systems can be defined in <user data directory>/data/universe/ranks.xml. Each system needs a code that is not already in use; a system that reuses a shipped code is rejected. See Ranks.md in this folder.
  • Award sets (.xml) can be placed in <user data directory>/data/universe/awards/. The file name is the set name, and a file with the same name as a shipped set replaces it. The award images go in <user data directory>/data/images/awards/<set name>/, in medals/, ribbons/ and misc/ subfolders.
  • Academies (.xml) can be placed in <user data directory>/data/universe/academies/.
  • Planetary systems: YAML files (.yml), each containing a single system, can be placed in <user data directory>/data/universe/planetary_systems/. Subfolders and .zip files containing .yml files can be used. A system with the same ID as a shipped system replaces it.
  • Campaign presets (.xml) can be placed in <user data directory>/data/campaignPresets/. When a user directory is set, presets you save from MekHQ are saved here (otherwise they go to the installation's userdata/data/campaignPresets/ folder).
  • Life Paths (.json) for the Advanced Character Builder can be placed in <user data directory>/advancedCharacterBuilder/lifePaths/. Note that this folder is not inside data/.
  • MekHQ's MegaMekLab tab opens its save dialogs in the user data directory.

Faction Logos

A faction's emblem, used in MekHQ (including on the interstellar map) and in MegaMek, comes from its icon field. This is a file name in data/images/universe/factions/; an image with that name in <user data directory>/data/images/universe/factions/ is used in preference to the installed one. The iconChanges field selects different images by game year. A command without an icon of its own uses the icon of its parent faction. 

icon: my_faction.png
iconChanges:
  3080: my_later_faction.png

Older faction files may use the logo and logoChanges fields instead. These still work in MekHQ, but only when the faction has no icon, and MegaMek ignores them. Their paths are relative to data/images/force/Pieces/Logos/, again preferring the copy in <user data directory>. For example, logo: Custom/My Faction.png uses <user data directory>/data/images/force/Pieces/Logos/Custom/My Faction.png if it exists. New faction files should use icon.

Factions with neither an icon nor a logo, or whose image cannot be loaded, use the generic Clan or mercenary logo. Use a PNG with a transparent background: the interstellar map draws the emblem's silhouette as a faint, faction-colored watermark rather than displaying the original colors. Independent and abandoned territories never show an emblem; otherwise the faction must own territory, and zoom, available territory size and collisions with other emblems still affect visibility. Selecting a campaign unit icon does not set a territorial faction emblem. Restart MekHQ after changing faction definitions or logo images.
